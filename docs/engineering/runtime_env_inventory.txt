open_gororoba runtime environment inventory
===========================================

Purpose
-------
This file is the repo-level inventory of environment variables that affect
runtime behavior. It separates secret-bearing variables from ordinary tuning
or CI variables so future cleanup does not confuse "config" with "credential."

Credential-bearing variables
----------------------------
These must stay user-local or secret-manager managed. Do not commit them into
the repository, shell scripts under version control, or checked-in env files.

- `NASA_API_KEY`
  Optional key for NASA DONKI requests in heliosphere ingestion. If unset, the
  runtime falls back to public CCMC endpoints rather than a bundled demo key.
- `SEMANTIC_SCHOLAR_API_KEY`
- `S2_API_KEY`
  Alias for Semantic Scholar.
- `CORE_API_KEY`
- `CINII_APPID`
- `UNPAYWALL_EMAIL`
- `ADS_API_KEY`
- `NASA_ADS_TOKEN`
  Alias for NASA ADS.
- `LENS_API_KEY`

Install pattern:

```bash
export NASA_API_KEY="replace-with-issued-nasa-api-key"
export SEMANTIC_SCHOLAR_API_KEY="replace-with-issued-semantic-scholar-key"
```

For the complete `lit_search` key list and placeholders, see
`docs/engineering/lit_search_env_vars.txt`. For the user-local bootstrap path
that installs the supported non-secret config surfaces, see
`docs/engineering/user_local_bootstrap.txt`.

Policy summary
--------------
- Secret-bearing variables belong in user-local shell rc files, session
  managers, or secret managers.
- Non-secret tuning variables may be set locally for development, CI, or
  benchmarking, but should remain out of versioned workspace dot-config.
- Cargo-provided build variables such as `OUT_DIR` and `CARGO_MANIFEST_DIR`
  are still part of the effective runtime surface when build scripts depend on
  them, but they are supplied by Cargo rather than installed by the user.
- If a new runtime variable is added, extend this inventory and classify it as
  either credential-bearing or non-secret.
- If a helper script installs local config, have it point back to this file and
  `docs/engineering/lit_search_env_vars.txt` rather than duplicating secret
  handling guidance inline.
